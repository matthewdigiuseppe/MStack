# GUIDE-LLM items (verbatim) + LaTeX skeleton

Loaded by `/mstack:llm-checklist` when compiling `report` or `latex`. Transcribe
the required items verbatim into the compiled checklist. "Log as" names the
ledger field in `.mstack/llm-usage.jsonl`.

## The 14 required items

**Scope of LLM use**
- **A.1 — LLMs were used in this project for:** *(log as `purpose`)*
- **A.2 — Degree of automation (human in the loop versus fully automated):** *(log as `automation`)*

**Model or system details**
- **B.1 — Model name, including provider, model size, exact version or identifier, date of access and source link (if possible):** *(log as `model.*` — a bare "ChatGPT"/"GPT-4" is not acceptable; give the dated/exact version)*
- **B.2 — Model access (for example, API, web interface or local) and context mode (for example, chat mode or separate calls):** *(log as `access_mode` + `context_mode`)*
- **B.3 — Relevant LLM configuration(s) reported (as applicable), such as temperature, maximum tokens, seed and number of runs:** *(log as `config.*`)*
- **B.4 — Customization:** *(log as `customization` — fine-tuning, RAG, tools/function-calling, retrieval, guardrails)*
- **B.5 — Did the LLM session(s) include persistent memory across interactions?** *(log as `persistent_memory`)*

**Prompts**
- **C.1 — Exact prompt(s) reported:** *(log as `prompt_user_ref` — a file path to the verbatim prompt)*
- **C.2 — System-wide instructions (if any):** *(log as `prompt_system_ref`)*

**Data inputs and privacy**
- **D.1 — Handling of personal or sensitive data (if any) (for example, consent for data processing):** *(log as `data_sensitivity`)*

**Validation and interpretation**
- **E.1 — Human validation of LLM outputs:** *(log as `human_validation` — e.g. inter-rater agreement vs a hand-coded gold set)*
- **E.2 — Describe any relevant post-processing (for example, filtering in case of format mismatches, unit conversions and so on):** *(log as `post_processing`)*

**Reproducibility**
- **F.1 — Code, notebooks or scripts for LLM calls shared:** *(log as `code_ref`)*

**Competing interests**
- **G.1 — Funding, support or other relevant relationships (including in-kind access to compute or models, or professional affiliations):** *(project-level; `_meta.competing_interests`)*

## Optional items (online version — did not reach the consensus threshold but recommended)

Map to `opt.*`: 1) justification for the LLM choice; 2) rationale for the prompt design; 3) comparison against other LLMs or methods (are the conclusions unique to one LLM or general?); 4) risks of training-data leakage (test materials seen during training, inflating performance); 5) assessment of potential bias or systematic differences in LLM behaviour (gender, racial, cultural); 6) conversation transcripts; 7) discussion of ethical implications (especially participant-facing chatbots); 8) computational resource use.
